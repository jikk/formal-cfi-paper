\heading{Safety of a single trace.}
Static CFI policies $\Pol$ are sets of virtual address edges $(a,a')\in\mathbb{N}^2$.
A trace $\tau$ is safe if all its computational steps are confined to edges in $\Pol$:
\begin{align*}
\mathit{steps}(\langle a,\sigma\rangle) &= [\,] \\
\mathit{steps}\big(\langle a_1,\sigma_1\rangle :: \langle a_2,\sigma_2\rangle :: \tau\big) &= (a_1,a_2)::\mathit{steps}\big(\langle a_2,\sigma_2\rangle :: \tau\big) \\
\safe{trace}(\Pol,\tau) &\equiv (\mathit{steps}(\tau)\subseteq\Pol)
\end{align*}

\heading{Safety of a rewritten trace.}

Since rewriters relocate and add instructions, the policy $\Pol\kern1pt'$ for the rewritten code must reinterpret policy $\Pol$ in three ways:
(1) Addresses in $\Pol$ must be mapped to their rewritten locations.
This remapping is defined by function \itoip (\autoref{eq:itoip}).
(2) New permissible edges must be added for inserted security checks, to allow the new checks to execute.
(3) The inserted checks may signal an alarm by jumping to a safe abort address $\mai$.
These three reinterpretations are formalized as
\begin{equation}
\begin{aligned}
  \Pol\kern1pt' =\:& \{(4\itoip(a_1/4),4\itoip(a_2/4))\:|\:(a_1,a_2)\in\Pol\}\:\cup \\
                  &\{(a_1',a_2')\:|\:a_1',a_2'\in[\itoip(i),\itoip(i+1)), i\in[0,|\ell|)\}\:\cup \\
                  &(\mathbb{N}\times\{\mai\})

\end{aligned}
\end{equation}

Programs $p$ started in machine states $\sigma_0$ exhibit a trace $\tau$ when executed, denoted $\langle p,\sigma_0\rangle\leadsto\tau$.
Relation $\leadsto$ is defined by the ISA semantic specification, and is nondeterministic;
\unpredictable{} operations in $p$ can cause $\langle p,\sigma_0\rangle\leadsto\tau_1$ and $\langle p,\sigma_0\rangle\leadsto\tau_2$ for multiple different traces $\tau_1\ne\tau_2$.

We prove safety of rewritten code in program $p$ under the following assumptions:
(1) initial state $\sigma_0$ starts in the ARM instruction mode,
(2) the new text segment in $p$ is located at \bip,
(3) the policy table data segment is located at \tbi and has endianness matching $\sigma_0$,
(4) the text and table segments have non-writable permissions,
and
(5) the starting \PC in $\sigma_0$ is the start of a \Block.
These starting assumptions are properties of the ELF editor and OS process loader,
whose verification is out-of-scope.

\heading{Soundness of a CFI implementation.}
For a CFI rewriter implementation $r$ to be sound, all executions of all rewritten programs it produces must be safe.
\begin{equation}
  \safe{CFI}(r) \equiv \forall \txt, \Pol, \langle r(\txt,\Pol),\sigma_0\rangle\leadsto\tau \Rightarrow \safe{trace}(\Pol\kern1pt',\tau)
\end{equation}

The soundness proof follows a coinductive structure that proves that any execution trace of any binary produced by the rewriter can be partitioned into \emph{trace slices}, each confined to a single \Block of the rewritten code.
The proof is coinductive because the trace and/or each slice within it could be infinitely long.
This proves that non-terminating programs continue to obey the policy, including those that loop infinitely within a \Block.

To perform the coinduction, the proof asserts an invariant at every \Block entry point, and proves that any trace slice that starts in an invariant-satisfying machine state either eventually reaches another invariant-satisfying state or never leaves the \Block.
The invariant consists of the five assumptions listed in \autoref{sec:verification}.
In particular, it posits that the instruction mode, code and policy data, endianness mode, and access permissions of security-critical sections have not been corrupted, and that the \PC is at a \Block boundary.

\Picinae transforms this invariant set into a case distinction that asks for a proof of invariant-preservation for every \Block that Rocq infers that the rewriter implementation could generate.
Each of these cases therefore proves that if the trace begins at the start of a \Block in a state that satisfies the assumptions, then execution eventually
(a) reaches the start of another \Block in a state that also satisfies the assumptions,
(b) exits to a policy-permitted, non-block location (\eg, the abort handler),
(c) raises a hardware exception, or
(d) never exits the \Block.
Moreover, the trace slice exhibited during this process is policy-satisfying.

Each of these cases entails proving properties of abstract code, since most generated \Blocks are functions of the input instruction that they replace, not a fixed, concrete list of instructions.
For example, \Block code may copy operands from an original instruction into encodings of new instructions that it generates.

\heading{Unchanged \Block.}
The corresponding \Block for most instructions just contains
the original instruction. We define an instruction to be safe if it can only
ever fall through to the next instruction or raise a hardware exception and can never change the
CPU's instruction mode or endianness. For these cases, we prove as a lemma that a \Block containing
a single safe instruction is safe as long as fallthrough is policy-permitted,
and that whenever the \Block remains unchanged,
the original instruction was a safe instruction where fallthrough is permitted.

\heading{Non-control-flow change.}
For instructions that are changed for non-control-flow reasons,
such as instructions that just reference the PC register without modifying it, we prove a
lemma similar to the previous case about \Blocks consisting entirely of safe instructions.
However, conditional instructions become \Blocks with a conditional branch at the start,
which is not a safe instruction, as it does not always fallthrough or raise an exception.
To handle this, we prove another lemma that if a \Block is safe, it is still safe after inserting a branch to the next
\Block at the beginning, which requires us to prove that the rewriter correctly computes an encoding that decodes to a
branch with the proper offset. With these lemmas, we can prove the safety of all \Blocks changed for non-control-flow reasons.

\heading{Direct control flow.}
Instructions that perform direct control flow must be modified to account for
the additional instructions we insert. We prove that our rewriter computes and uses the correct new offset when the destination
is permitted by the policy or replaces the instruction with a branch to the abort handler, and that both cases are safe.

\heading{Unsupported instructions.}
Instructions that we do not support,
such as those that always change the instruction mode or \unpredictable{} instructions,
are replaced with a branch to the abort handler, which we prove safe similarly to the previous case.

\heading{Indirect control flow.}
The code to lookup a destination from an instruction's policy table is the same for all indirect control flow instructions,
parameterized by the register containing the destination, the bits extracted by the hash function, and the address of the table.
We prove a lemma about this code that after executing this portion of the \Block,
the register contains some value from the table,
and a separate lemma that the relevant table consists entirely of permitted destination addresses for the instruction in question.
Proving the safety of indirect control flow \Blocks simply involves
(1) skipping over all of the instructions up to the table lookup,
since they are all either safe or a conditional branch to the next \Block
(2) applying the lemma about the table lookup code to skip to a state afterwards where we have
loaded from the table
(3) executing the rest of the \Block and reaching a state where we have transferred control
to the address from the table
(4) applying the lemma about the addresses in the table and concluding that we have
successfully reached another invariant point, since we are in a state in the same instruction mode and endianness
either at the start of a \Block for a permitted destination or the abort handler.

These cases cover every possible \Block generated by our CFI implementation, so a \Block is always safe.
Thus, we conclude that for all programs produced by the rewriter,
any trace beginning at the start of a \Block will only take steps permitted by the policy as long as it remains in the new text segment,
meaning our implementation is sound.
\qed
