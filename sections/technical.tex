The correctness specification of a CFI rewriter describes the rewriter's ability to enforce a control-flow policy for the programs it produces.
% A program abides by a given policy if all execution steps start and end in locations the policy whitelists.
A rewritten program abides by its policy if the control flow transfer from each IRM either goes to the abort destination or corresponds to a policy-permitted transfer in the original program.
A proof that a CFI rewriter conforms to this specification must therefore reason about all execution steps that may be taken in the produced program.

CFI rewriters replace instructions  with \emph{inline reference monitors} (IRMs), instruction sequences that constrain control-flow to the policy.
We can partition a processor's execution history into IRM block executions, enabling an inductive proof structure for the correctness of the rewriter.
To show that programs produced by the rewriter always abide by the policy, it suffices to show that all IRMs a rewriter produces abide by the policy.

% IRMs can be further segmented into four categories, leading to another tier of case analysis for a rewriter's correctness proof.
Each rewritten instruction falls into one of four categories, leading to another tier of case analysis for a rewriter's correctness proof.
It is either
\begin{enumerate}
    \item a safe instruction,
    \item a static jump (i.e., destination is known at compile time),
    \item a dynamic jump (e.g., function pointers, jump tables, returns), or
    \item an invalid instruction.
\end{enumerate}

Case~1 requires no rewriting.
Case~2 requires replacing the original jump target with a new location, as inserted instructions will relocate most code.
Case~3 requires augmenting the jump with a mechanism to ensure that the target is in the policy (e.g. a lookup table).
Case~4 requires replacing invalid instructions with jumps to an abort routine.

Thus, to prove that a CFI rewriter is correct, it suffices to show that all code generated by the rewriter in each of the above four cases never leaves the policy, or leaves the policy and abandons safety guarantees (e.g., syscall).
We show that our CFI rewriter implementation is correct by a proof that follows this inductive structure.
