\begin{abstract}
Binary \cfi has emerged as a cornerstone of software defense, with trusted implementations within VMs, OSes, hypervisors, web browsers, and many other security-critical products.
However, no full-scale binary CFI rewriter \emph{implementation} is yet proven secure against the hijacking attacks it purports to thwart.
Formal methods (FM) offer peak assurance for production software in a variety of domains, such as certified compilers, OS kernels, and networking stacks; but verifying binary-to-binary code rewriting software raises unique challenges that frustrate traditional FM\@.

\cav{Name suggestion: VFCFI? (VeriFied) Catchy}
\pname bridges this gap by implementing the first fully verified binary-to-binary CFI system for a mainstream microarchitecture.
A machine-checked proof in Rocq guarantees that rewriting generates policy-compliant binaries from near-arbitrary binary code inputs,
and the program-proof co-development process fixes subtle yet dangerous logic bugs that evade dynamic testing and only become exposed by exhaustive proof.
Verification is facilitated by a new approach to formalizing proofs that universally quantify over arbitrary (non-concrete) binary code inputs, leading to design principles for provably secure binary hardening implementations.
%[We should end with a sentence about experimental evaluation (to help reinforce that this is very practical --- important for CCS).]
Evaluation on SPEC CPU benchmarks, software libraries, and malicious exploits demonstrates that \pname exhibits performance, compatibility, and security suitable for production deployments.
\end{abstract}

(problem)

- **Control-Flow Integrity (CFI)** has become one of the most advanced and widely deployed defenses for protecting real-world production systems.
  - However, despite its prominence, a critical aspect --- *the correctness of its binary-level implementation and its impact on real-world effectiveness* --- remains underexplored.

(research)

- In this work, we present the *first formally verified CFI binary rewriter*, ArmCFI, establishing its safety and security by **machine-checked proofs of compliance** for both:
  - the real-world ISA (ARMv7), and
      - // realistic/practical representation of ARMv7?
  - a rigorously defined *fine-grained* CFI security specification.

- By doing so, our research eliminates reliance on *costly and inherently incomplete post-instrumentation validation via dynamic testing*.

- Our research is enabled by **Picinae**, which provides a principled ISA abstraction that supports **symbolic reasoning over arbitrary binary inputs**.
  - (optional) This capability allows us to **verify the rewriter once and guarantee soundness for all output binaries**, ensuring both ISA conformity and adherence to CFI security requirements.

(impact/result)

- Beyond the system itself, the paper contributes broader insights that **bridge formal methods and binary-level security engineering**:
  - (contribution 1) We derive **design principles for building formally verifiable binary-level security mechanisms**, and
  - (contribution 2) We showcase how formal verification exposes **subtle, implementation-level bugs** that are difficult to detect through testing alone.

  - (optional) Despite full formal verification, **ArmCFI achieves runtime overhead comparable to state-of-the-art CFI systems (on average XX\% for SPEC 2017)**.
  - (optional) we open-sourced/publicized the ArmCFI source base.

(vision/promise)
- More broadly, our research opens a new research avenue for *general methodology* for formally verified static binary rewriting exploring beyond CFI binary writer to a wider class of *inlined reference monitor (IRM)-based security mechanisms*.
