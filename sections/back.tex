CFI is a foundational security defense designed to protect against control hijacking attacks by restricting the set of valid control-flow transfers a program may execute at runtime. The level at which CFI is enforced depends on the available program representation. When source code is accessible, CFI is typically implemented as a compiler pass, optionally leveraging hardware support such as Intel CET for enforcement. When only a binary is available, CFI can be enforced via either dynamic instrumentation or static binary rewriting. Although dynamic instrumentation is precise, it is generally less favored due to its runtime overhead and transparency limitations.

Static binary rewriting is more efficient in practice, as instrumentation is limited to control-transfer instructions rather than the full instruction stream. The underlying challenge, however, lies in constructing a complete and accurate control-flow policy from the binary alone, a problem widely recognized as difficult and, in many cases, undecidable. This research specifically focuses on the correct implementation of binary-only CFI enforced through static binary rewriting. Other aspects, such as the generation of control-flow policies or optimization of runtime efficiency, are outside the scope of this work.

Secure IRMs take an untrusted binary as input and produce a hardened, rewritten binary augmented with additional security checks. By weaving security logic into the original binary, IRMs partition program execution into two distinct contexts: the guest context, which runs the original program, and the monitor context, which enforces the security policy.

IRMs vary considerably in their statefulness. \kwh{Static} binary CFI is an instance of a stateless IRM, in which the control-flow policy remains fixed throughout program execution and does not require persistent monitor state. Stateful IRMs, by contrast, maintain internal monitoring state across execution, such as shadow memory for dynamic information flow tracking, allocation and deallocation histories for memory leak detection, and similar policies.

Regardless of statefulness, protecting the monitor context from compromise by the untrusted guest context is a significant challenge, particularly given that both contexts execute at the same privilege level and any protection mechanism must operate without incurring prohibitive overhead. Although this challenge is orthogonal to the stateless enforcement of CFI addressed in this work, it represents a compelling direction for future research in formally verified binary rewriting, and we revisit it in \autoref{sec:disc}.

Recent advances in \emph{formally verified lifting} have opened new avenues for formally verified binary analysis, enabling verification of both correctness and security properties. However, existing frameworks reason over concrete binaries and cannot generalize to prove properties in which some or all the binary code is unknown. This limits their practical applicability to binaries known at verification time.

  Overcoming this limitation requires more than a proof assistant. Rather, it requires an abstraction layer that faithfully models real-world ISAs while supporting symbolic reasoning. \Picinae~\cite{picinae} provides this foundation. Built on Coq/Rocq, it models machine execution through memory state and execution traces and represents program state symbolically, allowing proofs that treat the binary itself as a variable. This enables verification results to generalize from a single program to the unbounded set of binaries a rewriter may encounter.

  This capability is essential for \pname. Frameworks that operate on concrete binaries can verify individual rewritten outputs but cannot prove that the rewriter is correct for all inputs. \Picinae~\xspace lifts reasoning from individual binaries to the rewriter’s behavior across all binaries, enabling the end-to-end correctness guarantees that \pname requires.
