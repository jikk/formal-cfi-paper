\section{Open Science}
We release our artifacts at \url{https://anonymous.4open.science/r/armcfi2026ccs}, including the full source code needed to understand, reproduce, and evaluate our system. The repository provides detailed documentation for rebuilding the formal proofs of compliance with both the CFI specification and the ARMv7 architecture, as well as instructions for building and compiling the \pname rewriter to generate CFI-instrumented binaries.

We also include PoC attack cases (\autoref{tab:poc-attacks}) together with automatically profiled control-flow policies. To facilitate deployment and experimentation, we provide a containerized environment (\eg Docker) that enables users to run \pname on compatible ARMv7 platforms and evaluate it on custom binaries.

\section{Hash Function Replacement}

This appendix outlines the work needed to replace the hash function with one that decreases the space overhead seen in \autoref{fig:spec2017_size} without compromising the soundness of the rewriter.
In \autoref{sec:fm_friendly} we list FM friendly design principles.
Another design principle that helps in this case is making the desired soundness/correctness properties independent of deep properties of the implementation.
For instance, the soundness of the rewriter does not depend on the cryptographic security or collision avoidance of the hash function.
