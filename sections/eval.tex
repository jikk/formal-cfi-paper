Beyond enforcement correctness, \pname supports flexible policy specification.
For these experiments, we applied a partial blacklisting policy that designates a function by
name (\eg \texttt{bad\_func()}) as an invalid control-flow destination.
\pname is designed to accommodate more comprehensive and realistic policies, such as
whole-program call-graph enforcement or fine-grained per-callsite constraints.

The following shows an example policy used for the basic security evaluation.

\begin{lstlisting}[language=c, linewidth=0.9\linewidth,caption={CFI policy example.\kjee{a dummy, placeholder}},label={lst:cfi_policy},captionpos=b,xleftmargin=.3cm]
/* Blacklist policy: deny control-flow transfers to bad_func() */
BLACKLIST {
    bad_func
}

/* All other control-flow transfers follow the default policy */
DEFAULT ALLOW;
\end{lstlisting}

Detailed documentation of the policy specification language is available in \texttt{POLICY.md} in the \pname repository\footnoteref{note0}.
