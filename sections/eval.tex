\subsection{Space Overhead}
Rewritten binaries take up more space than the original ones from the addition of the new text and policy table segments.
We measure the relative size of each for the rewritten SPEC binaries, shown in Figure \ref{fig:spec2017_size}.

On average, the new text segment is 1.36 times larger than the original text segment.
For the table segment, we also measure how many entries are filled with an actual program address compared to the abort handler.
Some benchmarks have very high space overhead mainly due to unfilled entries
when the table is forced to be unnecessarily large to differentiate between distinct addresses.
In these cases, using a better hash function can reduce the number of unfilled entries and the overall size of the table segment.
The table segment on average contributed 73.5\% of the added size.

\subsection{Functionality}
The SPEC CPU test suite includes checks if the benchmarks produce the correct output,
and all of the rewritten programs succeeded.
In addition, we tested the rewriter for functionality on other programs,
including GNU Core Utilities, Lua, CPython, Vim, Git, SQLite \mxz{list a few more programs}.
\pname does not require input binaries to be from a specific compiler.
We tested C and C++ binaries produced from GCC and Clang,
as well as other binaries from languages like Rust and Zig,
and found the rewritten programs to still function correctly.
