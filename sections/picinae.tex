\Picinae{} is a bottom-up \FMs framework that extends the Rocq proof assistant with facilities for machine-checked reasoning about source-free, stripped native code on a variety of ISAs\@.
\autoref{fig:picinae} illustrates its typical workflow.
Concrete binary code is first lifted to a low-level \IL that encodes each machine instruction's operational effects upon the machine state.
Lifting can be performed externally or internally.
External lifting uses a separate binary reverse-engineering tool, such as NSA Ghidra~\cite{ghidra} or the Binary Analysis Platform (BAP)~\cite{brumley11cav}, to convert machine code to the tool's \IL (P-code or BIL, respectively), which translates directly to \Picinae{}'s IL\@.
Internal lifters implement this within Rocq rather than as an external tool.

To realize \pname, we implement an internal lifter for ARMv7\@.
Internal lifting has the advantage that it need not be applied to concrete machine code.
% caverill: Is this notation explained anywhere, or worth the space?
Each internal lifter is a Gallina function $\lceil\cdot\rceil:\mathbb{N}^*\rightharpoonup s$ that specifies the general process of translating byte lists $\ell\in\mathbb{N}^*$ to IL statements $s$ for a particular ISA\@.
Rocq theorems and proofs can thereby abstractly refer to the IL representation $\lceil\ell\rceil$ of arbitrary (unknown) byte list $\ell$.
The lifter decodes bytes to assembly instructions and translates assembly instructions to IL without performing full disassembly or control-flow recovery (which are Turing-undecidable tasks on many architectures in the general case).
This keeps the lifter small and amenable to abstract formal reasoning.

Figure~\ref{fig:picinae_il} summarizes \Picinae{}'s IL, which is strategically chosen to bridge the semantic gap between real binary software and the formalisms expected by automated theorem provers.
Each machine instruction is represented as a statement $s$ that explicitly encodes its semantic effects upon the machine state, including assignments of expression computations $e$ to machine state variables $v$ (e.g., cpu registers and memory), control-flow transfers ($\mathtt{jmp}$), hardware exceptions ($\mathtt{exn}$), sequences (\texttt{;}), conditionals (\texttt{?}), and bounded microcode loops ($s^e$).
IL expressions $e$ range over variable-reads $v$, $w$-bit binary constants $n\ofwidth{w}$, $w$-width memory-reads and writes $e_1[e_2 (\coloneqq e_3)]\ofwidth{w}$, binary arithmetic and logical operations $\circledcirc$, $w$-bit typecasts, local bindings ($\mathsf{let}$), and non-deterministic processor effects $*\ofwidth{w}$.
Together, these form a type-safe Turing-complete computational language sufficient to express microarchitectural machine semantics with a minimal trusted computing base.

\Picinae{} provides an array of powerful facilities for semi-automated, formal, machine-checked reasoning about the lifted \IL, including a fully machine-verified symbolic interpreter, IL type-checker, binary arithmetic symbolic expression simplifier, and theories of modular arithmetic, memory safety, dynamic trace analysis, interprocedural analysis, binary data structures, mixed endianness and two's complement arithmetic, and temporal logics.
This facilitates generation and verification of machine-checked proofs of binary code properties without source code, such as control-flow safety, memory safety, process isolation, timing leak-freedom, and even complete functional correctness for many concrete codes.

Proof generation is semi-automated and human-guided.
An expert user typically supplies a high-level structure for the proof by asserting invariants at particular code points.
\Picinae's tactic automation then generates a coinductive proof by slicing the code at invariant points, performing symbolic interpretation along all potential control-flow paths, auto-solving or auto-simplifying many symbolic expressions and proof goals, and prompting the user for assistance with any remaining goals that cannot be solved automatically.
None of the automation is trusted; all tactics generate independently Rocq-verifiable proofs of soundness for all results, including symbolic interpretation, soundness and completeness of any control-flow recovery results, and all binary symbolic expression simplification.
The result is a completely machine-checkable proof of each theorem.

\Picinae{} is well-suited for reasoning about binary rewriters because it leverages Rocq's support for dependently-typed coinduction.
Dependent types attach provable properties to the untyped binary values that populate machine code programs, allowing tactic automation to generate proofs programmatically from values during symbolic interpretation.
Coinduction affords formal reasoning about potentially non-terminating code, avoiding difficult termination proof obligations for machine code with unstructured control-flows and unbounded loops.
This facilitates principled, automated reasoning about underconstrained codes drawn from an untyped, unstructured machine language.
